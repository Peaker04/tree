# NOVYX Mobile UI/UX Governance Critique

## Scores

- Nielsen design health: **25/40 — Acceptable; systemic governance cleanup required**.
- Native technical audit: **11/20 — Acceptable; significant work remains**.
- Technical dimensions: Accessibility 2/4, Performance 2/4, Appearance/Theming 2/4, Platform Conformance 3/4, Adaptivity 2/4.

## Design specificity

NOVYX has a defensible product identity: Vietnamese-first botanical field operations, evidence-led and interruption-safe. The implementation currently mixes two eras: the older Seed/Linear pill-and-card vocabulary in root `DESIGN.md` and the newer Living Botanical Operational vocabulary in `.design/.stitch`. Root `DESIGN.md` remains normative, so agents can follow project instructions exactly and still recreate the older appearance.

UI-UX Pro Max returned an App Store landing/exaggerated-minimalism result with orange/blue marketing colors; `.planning/NOVYX_MOBILE_UI_CLEAN_RESET_PLAN.md` correctly rejects it. Taste Skill is present only as a quality filter because it excludes native multi-step product UI. Impeccable is absent from project skill routing.

## Priority findings

1. **P0 — Blocked-work CTA is a no-op** (`ManagerDashboard.tsx:42-46,173-174`). The highest-priority action gives no feedback.
2. **P1 — Design authority is split** (`DESIGN.md:300-397`, `.design/DESIGN.md:36,64`, `.stitch/DESIGN.md:55,70,143-150`). Pill buttons, tiny metadata and uniform surfaces conflict with the newer rounded-rectangle, >=13px, varied-mass direction.
3. **P1 — UI tests lock source shape** (`tests/mobile/ui-foundation.spec.ts:124-140,204`). Tests require `heroCard`, `metricsBar` and exact source strings; behavior-preserving redesigns can fail and encourage restoration of old source structure.
4. **P1 — Dashboard exception actions lose business intent** (`ManagerDashboard.tsx:59,186,194,261,292`). Overdue routes to Review regardless of eligibility; resume/cancel use hard-coded reasons.
5. **P1 — Governance is prose-only** (`AGENTS.md:27-30,39`, `mobile-ui-ux/SKILL.md:43-50`). No gate proves FR/NFR reasoning, spatial composition, skill research or device evidence was applied. Screen contracts remain proposed.
6. **P2 — Visual hierarchy is flattened** (`packages/ui/src/index.ts`, `AppPrimitives.tsx:452-539`, `ManagerDashboard.tsx:116-222,475-583`, `StaffHome.tsx:120-165,199-222`). Green, cards, pills and subtle shadows repeat across roles; Manager Dashboard also uses weight 700.
7. **P2 — Scale/accessibility gaps** (`TreeScopeSelectorSheet.tsx:195-314`, `AppPrimitives.tsx:60-86,279-330`, `UserAvatar.tsx:22`). Growing tree results use ScrollView + map, headings lack header semantics and avatar initials disable scaling.

## Root cause of apparent reversion

1. Design docs do not affect runtime; TSX and Metro bundles do.
2. Root `DESIGN.md` still encodes the older visual vocabulary.
3. New `.design/.stitch` direction was committed as evidence but not reconciled into root authority before implementation.
4. Source-string tests preserve old component/style names.
5. Recent UI work reintroduced hero cards, shadows, metric pills and weight 700.
6. Screen contracts are proposed and Android/device gates remain pending.
7. Metro/update caching is possible but not proven. Root app/config entrypoints delegate correctly and are not duplicate implementations.

## Positive findings

- Strong Vietnamese domain language and role navigation.
- Semantic tokens, reusable primitives, safe-area ownership and contextual permissions.
- Review validation preserves user input and blocks approval with evidence gaps.
- Core task/tree/review collections use virtualized lists.

## Recommended sequence

Reconcile one authoritative design contract; replace implementation-coupled UI tests with observable contract tests; repair action semantics; mechanically enforce the UI harness; then perform color/layout/typography enhancement and device acceptance.
